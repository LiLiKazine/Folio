# Reading a Book Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Opening a Book shows its Pages one per screen; turning Pages moves the Book's Reading Position; the Library reflects it; Notices appear over whichever screen is on top.

**Architecture:** FolioCore gains one Library operation (`turnPage`) and one event (`readingPositionChanged`). In the app, a new per-window root view `LibraryWindow` owns the NavigationStack path and every dialog (the existing `PresentationQueue` moves up from `LibraryView`), so a Notice is presented above both the Library and the pushed reading screen. The reading screen lives in a new `app/Folio/Reading/` folder: a paged view of `PageView`s fed by an ImageIO decoder that downsamples to the window and caches the current Page and one each side.

**Tech Stack:** Swift 6 strict concurrency, SwiftUI, Swift Testing, ImageIO, OSLog. No third-party code.

**Spec:** `docs/superpowers/specs/2026-11-08-reading-design.md` (the glossary `CONTEXT.md` is authoritative for terms).

## Global Constraints

- Glossary terms exactly as in `CONTEXT.md`; never the words under _Avoid_ (no "thumbnail", "progress", "bookmark", "reader" for the screen).
- Swift 6 language mode, strict concurrency, `async`/`await` and actors; SwiftUI only. Wrapping UIKit/AppKit is allowed only if SwiftUI cannot do it, recorded in `DECISIONS.md`.
- Warnings are errors. `./scripts/test.sh` passes `-Xswiftc -warnings-as-errors` to FolioCore; run the script, not Xcode, to prove the package clean.
- Swift Testing, not XCTest. OSLog, not `print`.
- User-facing strings go in `Localizable.xcstrings`, synced with `xcrun xcstringstool sync` using stringsdata from both platforms; restore compact `{}` entries afterwards.
- A `catch` that only logs needs a comment at the site saying why nothing the user sees depends on it. This slice has two sanctioned log-only sites (Reading Position save, open record), both referencing the spec.
- Reading Position is a 0-based index into `Book.pages`; the UI shows "Page n+1 of N".
- Run `./scripts/format.sh` before each commit; `./scripts/verify.sh` must be green on macOS and iOS before the branch is finished.
- Work in the worktree `/Users/leo/Developer/Folio-reading` on branch `feature/reading`. Commit with the `structured-commit` skill; append each commit to `docs/logs/2026-11-08-06-reading-design.md`'s Commits table.

## Review Focus

Inputs the spec implies but no single feature test exercises; each has a test pinned to a task below.

1. A Book with exactly one Page: the slider has a range of one value, forward and back swipes do nothing, the counter reads "Page 1 of 1". (Task 5)
2. A stored Reading Position past the end of `pages` (an older edition had more Pages): opening must not crash and must land on the last Page. (Task 5, through `startIndex(for:)`)
3. A Page file deleted from disk after Import: `PageImage.decode` returns nil and the placeholder shows, like an undecodable file. (Task 4)
4. A burst of turns from the scrubber: the last `turnPage` wins and the stored position equals the final index, with no Notice. (Task 2)
5. A Book removed from the Library while it is open (another window on Mac): the reading screen stays until closed; `turnPage` then throws `.notFound(.turnPage)`, which is logged, not shown. (Task 2)
