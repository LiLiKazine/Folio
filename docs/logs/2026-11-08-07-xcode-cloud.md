# 2026-11-08-07: Xcode Cloud configuration

**Status:** Implemented (workflow not yet created; it is made in Xcode)

## Context

The owner asked to set the project up for Xcode Cloud: archive and TestFlight
for iPhone, iPad and Mac, under the personal team. The repository already had a
shared `Folio` scheme and a GitHub Actions workflow, and deliberately no signing.

## Options

| Question | Chosen | Rejected and why |
|----------|--------|------------------|
| Where signing lives | `Release.xcconfig` only | Xcode's Signing pane: it writes the team into `project.pbxproj` for Debug as well, so every build would need the Apple account, which the GitHub Actions runner does not have |
| Build number | Written from Xcode Cloud's number, archives only | A fixed 1 (TestFlight refuses repeats); bumping `Version.xcconfig` by hand per upload |
| FolioCore warnings | The hook runs the package tests with warnings as errors | Trusting the scheme: Xcode hides package warnings, so the project's own rule would be bypassed |
| Export compliance, Mac category | Left to the owner | Setting them here: they are the owner's declarations |

## Decision

Sign Release only, number archives from Xcode Cloud, hold FolioCore to its
warnings rule, and leave the workflow and the owner's declarations to the owner.

## What Changed

- `app/Config/Release.xcconfig`: automatic signing, team `PJBUF7JSHK`.
- `app/ci_scripts/ci_pre_xcodebuild.sh`: new.
- `DECISIONS.md`: an Xcode Cloud section.

## What Was Discovered

- The number in brackets on a signing certificate in Xcode ("Apple Development:
  Li Sheng (D9HKP4NYZL)") is the certificate's own ID, not the Team ID. The team
  is `PJBUF7JSHK`, as the matching Apple Distribution certificate and the
  project file Xcode wrote show.
- Turning on "Automatically manage signing" in Xcode wrote signing into both
  Debug and Release in `project.pbxproj` and overrode the `.xcconfig` files:
  `xcodebuild -showBuildSettings` showed Debug as Automatic with the team. That
  was reverted and moved to `Release.xcconfig`; afterwards Debug showed Manual
  and Release Automatic with the team.
- Builds checked: Debug and Release, iOS and macOS, all succeed. The hook was
  rehearsed on a copy for the three actions (archive sets the number, build does
  nothing, build-for-testing runs the 85 FolioCore tests). It has not yet run on
  Xcode Cloud.
- Build 1 on Xcode Cloud: the hook ran, the archive and all three exports
  succeeded, and the run failed at the next step, "Preparing build for App
  Store Connect". The archive's own log zip holds no error; the cause was found
  through the App Store Connect API (`asc xcode-cloud issues list`). The app
  had no icon: every slot in `AppIcon.appiconset` was empty, and App Store
  Connect refuses a build without a 1024 px icon.
- The icon was chosen on a Claude Design canvas (an F monogram on mustard,
  ground #E0A400, mark #1B1E26) and rendered to PNG with a small CoreGraphics
  script rather than exported from the canvas, so the pixels are exact. Both
  deployment targets are 26.0, whose systems apply their own icon mask, so the
  PNGs are full-bleed squares with no inset or shadow.
